## Findings

1. **high — `agents/fuzzer_agent.py:192`, `agents/fuzzer_agent.py:211`: Registry changes survive failed campaigns and matrix writes.** With migration A active, a request for migration B resets A’s registry immediately. If B’s campaign raises `CampaignError`, or its matrix upsert fails, `self.matrix`, `self.migration`, and the room document still describe A while the registry has been cleared or populated for B. A subsequent A re-verification skips reset and can assign A’s former D-3/D-5 divergences to D-1/D-2, applying decisions to the wrong clusters. **Fix:** Run against a staged registry, retain the committed mapping through failures, and commit a recoverable registry snapshot together with the matrix. Preflight matrix ownership before resetting state or running probes.

2. **high — `agents/fuzzer_agent.py:144`, `agents/fuzzer_agent.py:197`: Restart rehydration does not reconcile the registry with the restored matrix.** After A discovers D-1 through D-5, restart with its room matrix intact but its registry file missing or containing invalid JSON. The matrix restores migration A, so the next A campaign skips reset; `Registry._load()` silently supplies an empty mapping. On the demo build, the former D-3/D-5 become D-1/D-2. Previously recorded unclassified clusters can also disappear entirely from subsequent reports. **Fix:** Persist and restore the registry mapping and discovery evidence with the matrix, or announce an inconsistent/missing registry and refuse campaigns until repaired. Do not silently continue with an empty registry for an existing migration.

3. **medium — `agents/fuzzer_agent.py:255`, `agents/fuzzer_agent.py:267`: Revision polling exceeds the 30-second contract and accepts late success.** A mismatch just before the deadline leads to a full sleep and another request with a fixed five-second timeout. A matching response received after 30 seconds returns `True` before the deadline is checked, allowing the campaign to start late. **Fix:** Check the deadline before each request and before accepting success, clamp sleeps to the remaining budget, and enforce the remaining wall-clock budget on requests.

4. **medium — `agents/fuzzer_agent.py:133`, `agents/fuzzer_agent.py:140`, `agents/fuzzer_agent.py:146`: Rehydration failures can terminate startup without a room warning.** A fuzzer-owned matrix containing `{"kind":"matrix","runs":[1]}` passes the shallow validation, then raises `AttributeError` when reading the latest run’s trigger. A document-loading exception also escapes directly. `RoomAgent.run_forever()` calls `on_connected()` outside its protected dispatch path, so these failures terminate the agent without the required `⚠️` report. **Fix:** Validate run and trigger shapes before assigning restored state, catch startup document/schema failures, announce them, and keep campaigns blocked until state is recovered or an explicitly announced fresh-state recovery succeeds.

5. **medium — `agents/fuzzer_agent.py:262`, `agents/fuzzer_agent.py:309`, `agents/fuzzer_agent.py:313`: Error messages forward executable mentions.** For a valid shadow-test request, a matching metadata response such as `{"rev":"abcdef","import_error":"failed importing @translator status"}` is posted verbatim inside the warning. Backticks do not neutralize Switch mentions, so this addresses the translator unintentionally. Malformed ledger IDs and invalid decision values can produce the same effect through error interpolation. **Fix:** Apply `_defuse_mentions()` to every posted body containing external metadata, ledger values, or exception text, including failure paths. Add adversarial mention tests for these paths.

6. **medium — `agents/fuzzer_agent.py:307`: Malformed decision state silently becomes an empty decision map.** A translator-owned ledger with the correct migration and `"decisions":[]`, `false`, or an absent `decisions` field passes through `state.get("decisions") or {}` as `{}`. A handoff without carried decisions then starts a campaign without announcing that its system-of-record state was malformed. This violates the fail-loud fallback rule and bypasses decision validation. **Fix:** Require the ledger’s `decisions` field to be a dictionary and reject malformed or missing fields with `MARK["error"]` before changing registry state.

7. **medium — `agents/fuzzer_agent.py:306`: Canonicalization silently overwrites contradictory ledger decisions.** A ledger containing `"D-1":{"decision":"preserve"}` followed by `"D-01":{"decision":"deprecate"}` becomes `{"D-1":"deprecate"}`. A carried `deprecate D-1` then passes the equality check even though the ledger contains conflicting verdicts for the same normalized ID. **Fix:** Normalize entries individually and reject duplicate normalized IDs with conflicting decisions, matching `parse_decisions()` behavior.

8. **low — `tests/test_fuzzer_agent.py:287`, `tests/test_fuzzer_agent.py:291`: The restart test does not verify its claimed absence of a registry reset.** An implementation that unconditionally resets the registry before every campaign still passes this test: rerunning the same naive corpus recreates exactly D-1 through D-5, history still advances to run 2, and the “ids restart” announcement remains controlled by the unchanged migration flag. **Fix:** Spy on `Registry.reset()` during the post-restart campaign, or seed an additional registry entry whose survival is asserted independently of the repeated corpus.
