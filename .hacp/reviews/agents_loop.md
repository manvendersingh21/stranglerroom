## Findings

1. **High — A replayed `approve-cutover` after a human rollback flips the proxy back to modern, and the loop test never exercises rollback.** `agents/cutover_agent.py:313-328` (approval path), `agents/cutover_agent.py:394-433` (rollback path); `tests/test_agents_loop.py:208-221` (only approval is exercised), `tests/test_agents_loop.py:346` (`assert scorecard["rollbacks"] == []`), `tests/test_agents_loop.py:236-250` (restart sends a *new* approval, not a replay).  
   **Failing scenario (reproduced with `tests/test_agents_loop_probe.py`):** complete the normal loop so `proxy_control.status(...)["target"] == "modern"`, then send the human command `@cutover-gate rollback`. The gate replies `↩️ Rollback complete: :60491 serves the legacy web.py service (:38783) again — requested by @user (message \`sw_75b2e33a2f0a\`). Verified: … Recorded in the Cutover Scorecard.` and the proxy is back on `legacy`, with `scorecard["cutover"] is None`. Now dispatch the original approval event again (same `message_id`, as a reconnect/re-delivery would). `_approve` takes the non-idempotent path because `cutover` is `None`, and emits `🚦 Cutover complete: :60491 now serves the modern FastAPI service (:37955) — approved by @user (message \`sw_f6b1db3758bb\`) …` plus `@translator record-cutover rev=f7d3e45a85f2 migration=MIG-20261105-054140`. The test cannot catch this because it never sends `rollback`, and `check_scorecard` actively asserts that no rollback exists.  
   **Minimal fix:** in `CutoverAgent._approve`, treat an approval message that is already recorded in `cutover_history` (or that predates the latest `rollbacks` entry) as stale: refuse it with a `MARK["error"]` and require a new `approve-cutover` after a rollback. Add a test phase that performs the human rollback, replays the old approval event, and asserts `proxy_target == "legacy"` and `scorecard["cutover"] is None`.

2. **Medium — The restart phase discards every `on_connected()` message, so a failure announced during rehydration is invisible and phase 7 still passes.** `tests/test_agents_loop.py:84-104` (the fixture calls `agent.on_connected()` at lines 102-103), `tests/test_agents_loop.py:239-249` (only messages produced after the later `again = room.human_says(APPROVE_EXAMPLE)` are inspected); the fuzzer's rehydration error is emitted at `agents/fuzzer_agent.py:211-232`.

Start a new migration (the translator's \`migrate\`) to renumber from scratch.` That message is posted before `again`, so it is absent from `out`; phase 7 still produces `Cutover for rev … is already complete …`, `@translator record-cutover …`, and `ℹ️ migration … is already sealed …`, and every assertion from lines 242-250 passes.    **Failing scenario (reproduced):** after the normal decision step, the ledger is at `patching` with builds `[(1, 'c3641e5018eb'), (2, '720b1dc8ebff')]`. Post the exact same `@translator preserve D-1 D-2 D-4 and deprecate D-3 D-5` again as a new message. The duplicate human command (a client retry or a double post) silently changes the deployed service after v2 was already verified, invalidating the benchmark and approval request instead of being a no-op.  
   **Minimal fix:** before rebuilding, compare the requested decision map with `state["decisions"]` for the open migration; if they are identical and the migration is already `patching`/`parity-approved`, reply that the decisions are already applied and do not deploy, append trail entries, or hand off. Add a probe that re-sends `DECIDE` as a new message and asserts the build count and status are unchanged.

## Verdict

**Request changes.** The happy-path loop is sound: `tests/test_agents_loop.py` passed three consecutive runs (7.72 s, 7.50 s, 7.58 s), and `tests/test_translator_agent.py tests/test_fuzzer_agent.py tests/test_cutover_agent.py` passed 62 tests. However, the test's coverage stops exactly where the reproduced defects are: it never exercises rollback or replayed events, it drops all restart-time output, it stops transcript checks before restart, and it never retries a decision command. Finding 1 is a production-routing regression that the loop should have caught; findings 2-4 leave the test's stated restart/idempotency/MARK guarantees unverified. The checks that did hold: agent-issued `migrate`, `preserve`/`deprecate`, and `rollback` all produced `🛑 Governance gate`, and the test uses a tmp `lists.py`, tmp state files, and free ports.
